## Spacing Scale

Material 3 uses dp (density-independent pixels) as the unit. This project follows the 4dp base grid throughout the existing Meld UI.

| Token | Value | Compose Equivalent | Usage |
|-------|-------|--------------------|-------|
| xs | 4dp | `4.dp` | Icon gaps, inline padding |
| sm | 8dp | `8.dp` | Compact element spacing |
| md | 16dp | `16.dp` | Default content padding, card insets |
| lg | 24dp | `24.dp` | Section spacing |
| xl | 32dp | `32.dp` | Layout section gaps |
| 2xl | 48dp | `48.dp` | Major section breaks |
| 3xl | 64dp | `64.dp` | Page-level vertical spacing |

Exceptions:
- Navigation bar item touch target: 48dp minimum height (Material 3 requirement, not a 4dp exception — 48 is a multiple of 4)
- Bottom navigation bar total height: 80dp (Material 3 NavigationBar default; includes 8dp top padding + 16dp icon area + label + 16dp bottom padding)

Source: 4dp base grid is the existing Meld pattern; no custom spacing overrides found in codebase.

## Color

This app uses Material 3 dynamic color. All color references use `MaterialTheme.colorScheme.*` — never hardcoded hex values in Compose code. The default seed color is `#ED5564` (defined as `DefaultThemeColor` in `Theme.kt`). On Android 12+ with the default seed, wallpaper-based dynamic color applies.

The pureBlack mode sets `surface` and `background` to `Color.Black` when enabled in dark theme.

| Role | M3 Token | Default Seed Approximation | Usage |
|------|----------|---------------------------|-------|
| Dominant (60%) — surfaces | `colorScheme.surface` / `colorScheme.background` | Dark: ~#1C1414, Light: ~#FFF8F7 | BridgeScreen background, Scaffold surface |
| Secondary (30%) — containers | `colorScheme.surfaceContainer` | Dark: ~#2E2020, Light: ~#F3E8E7 | NavigationBar container, card surfaces |
| Accent (10%) — selected state | `colorScheme.primary` | Derived from #ED5564 seed | Nav item selected indicator, selected icon tint |
| Destructive | `colorScheme.error` | ~#FF897D | Error state text and icon in BridgeUiState.Error |

Accent (`colorScheme.primary`) is reserved for:
1. The selected NavigationBarItem indicator (rendered automatically by Material 3 `NavigationBarItem`)
2. The selected tab icon tint (rendered automatically by `NavigationBarItem`)
3. No other elements in Phase 2 use accent color — the screen content is placeholder only

pureBlack mode: When active, BridgeScreen inherits `Color.Black` background via `MaterialTheme.colorScheme.surface`. No explicit handling required in BridgeScreen — it is inherited from `MetrolistTheme`.

Source: `Theme.kt` — `DefaultThemeColor`, `pureBlack()` extension, dynamic color logic.

## Component Inventory

Phase 2 adds one new screen and two new drawables. All other components are existing Material 3 primitives already in use.

### New: `BridgeScreen` composable

Location: `app/src/main/kotlin/com/metrolist/music/ui/screens/bridge/BridgeScreen.kt`

Structure:
```
Scaffold (topBar = TopAppBar with "Bridge" title, scrollBehavior)
  └── Column (fillMaxSize, verticalArrangement = Center, horizontalAlignment = CenterHorizontally)
        └── when (uiState) {
              Idle        → placeholder text: "Find a bridge between two artists"
              Searching   → placeholder text: "Searching… (${state.foundHops}/${state.totalHops} hops)"
              PathFound   → placeholder text: "Path found: ${state.path.size} artists"
              PlaylistReady → placeholder text: "Playing bridge playlist"
              Error       → placeholder text using colorScheme.error tint: state.message
            }
```

TopAppBar: `TopAppBar` with `scrollBehavior` parameter (matching Home/Library pattern). Title uses `titleLarge` typography. Uses `LocalPlayerAwareWindowInsets` for bottom inset so the mini player is accounted for.

### New: Bridge tab icon pair

| File | State | Approach |
|------|-------|----------|
| `bridge_outlined.xml` | Unselected (inactive) | Reuse `explore_outlined.xml` path data; same stroke-only compass/explore icon |
| `bridge_filled.xml` | Selected (active) | Copy `explore_outlined.xml` and change fill to solid (remove stroke, use filled path data variant) |

Decision: Reuse the explore/compass icon for Phase 2 (semantically appropriate — exploration/discovery). A branded icon pair is deferred as cosmetic polish. Source: RESEARCH.md open question 1, confirmed as acceptable for MVP.

## Interaction Contract

### Tab tap — Bridge selected

Trigger: User taps Bridge NavigationBarItem
Behavior:
1. `navController.navigate("bridge") { launchSingleTop = true; restoreState = true; popUpTo(startDestination) { saveState = true } }` — existing `onNavItemClick` lambda in `MainActivity.kt` already does this for all tabs
2. Bridge back stack is isolated from Home/Search/Library back stacks — handled by `launchSingleTop` + `saveState`
3. No animation override — use NavHost default crossfade transition (matches existing tab behavior)
4. Haptic: none (existing tabs do not trigger haptic on tap; only long-press on Search triggers haptic)

### Tab tap — Bridge already selected (re-tap)

Behavior: No navigation occurs (`launchSingleTop = true` prevents duplicate destination). BridgeScreen stays as-is. This matches Home/Library re-tap behavior.

### State transitions (Phase 2 — placeholder only)

All state cases in `BridgeUiState` must be represented in the `when` block. No actual transitions are wired in Phase 2 — `BridgeViewModel` stays at `Idle`. Future phases emit new states.

| From | To | Trigger | Phase |
|------|----|---------|-------|
| Idle | Searching | User taps "Find Bridge" (Phase 4) | Phase 4 |
| Searching | PathFound | JS bridge returns path JSON (Phase 3) | Phase 3 |
| PathFound | PlaylistReady | Playlist auto-starts (Phase 5) | Phase 5 |
| Any | Error | No path found or computation failed (Phase 4) | Phase 4 |
| Error / PlaylistReady | Idle | User taps reset (Phase 4) | Phase 4 |

## `BridgeUiState` Sealed Class Contract

Location: co-located in `BridgeScreen.kt` for Phase 2. Extract to `BridgeUiState.kt` if it grows in a later phase.

All subclasses annotated `@Immutable` per codebase convention (CLAUDE.md: "@Immutable on data classes in model layer is standard here").

| State | Class type | Data fields | Notes |
|-------|-----------|-------------|-------|
| `Idle` | `object` | none | Singleton — no data |
| `Searching` | `data class` | `foundHops: Int = 0`, `totalHops: Int = 0` | BRDG-04 feedback data for Phase 4 |
| `PathFound` | `data class` | `path: List<String>` | Artist name list — type refined in Phase 5/6 |
| `PlaylistReady` | `data class` | `path: List<String>`, `nowPlayingIndex: Int = 0` | PLAY-07 current-artist highlight for Phase 6 |
| `Error` | `data class` | `message: String` | BRDG-06 error copy |
