The file must contain:

```kotlin
package com.metrolist.music.di

import android.content.Context
import android.webkit.WebResourceRequest
import android.webkit.WebResourceResponse
import android.webkit.WebView
import android.webkit.WebViewClient
import androidx.webkit.WebViewAssetLoader
import dagger.Module
import dagger.Provides
import dagger.hilt.InstallIn
import dagger.hilt.android.qualifiers.ApplicationContext
import dagger.hilt.components.SingletonComponent
import timber.log.Timber
import javax.inject.Singleton

@Module
@InstallIn(SingletonComponent::class)
object BridgeModule {

    @Singleton
    @Provides
    @BridgeWebView
    fun provideBridgeWebView(
        @ApplicationContext context: Context,
    ): WebView {
        Timber.d("BridgeModule: Creating singleton WebView")

        val assetLoader = WebViewAssetLoader.Builder()
            .addPathHandler("/assets/", WebViewAssetLoader.AssetsPathHandler(context))
            .build()

        return WebView(context).apply {
            settings.javaScriptEnabled = true
            settings.domStorageEnabled = true
            settings.databaseEnabled = true
            settings.allowFileAccess = false
            settings.allowContentAccess = false

            webViewClient = object : WebViewClient() {
                override fun shouldInterceptRequest(
                    view: WebView,
                    request: WebResourceRequest,
                ): WebResourceResponse? {
                    return assetLoader.shouldInterceptRequest(request.url)
                }

                override fun onPageFinished(view: WebView?, url: String?) {
                    super.onPageFinished(view, url)
                    Timber.d("BridgeModule: EccoPath loaded at %s", url)
                }
            }

            loadUrl("https://appassets.androidplatform.net/assets/eccopath/index.html")
        }
    }
}
```

Key design decisions in this code:
- `@Singleton` + `@BridgeWebView` qualifier: per D-03, survives config changes and full app lifecycle
- `WebViewAssetLoader.AssetsPathHandler(context)` with path `/assets/`: maps `https://appassets.androidplatform.net/assets/eccopath/*` to `app/src/main/assets/eccopath/*`
- `javaScriptEnabled = true`: required for EccoPath to execute
- `domStorageEnabled = true`: required for IndexedDB persistence (INFRA-03)
- `databaseEnabled = true`: legacy Web SQL flag, harmless to enable per research
- `allowFileAccess = false`, `allowContentAccess = false`: not needed since WebViewAssetLoader handles all asset loading
- Timber logging for lifecycle debugging (following project Timber convention)
- Per D-01: This WebView is headless (never added to any layout). It only performs computation.

Modify `App.kt` to trigger the Hilt singleton WebView creation during `onCreate()`. The WebView MUST be created on the main thread, and `App.onCreate()` runs on the main thread -- so this is safe.

The approach: Inject the `@BridgeWebView WebView` into the App class via Hilt's `EntryPoint` pattern. Since `App` is the `@HiltAndroidApp` class, use `EntryPointAccessors.fromApplication()` to access the WebView singleton, triggering its creation.

   ```kotlin
       fun bridgeWebView(): WebView
   }
   ```
