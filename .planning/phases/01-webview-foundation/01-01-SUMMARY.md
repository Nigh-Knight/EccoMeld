## Decisions Made
- **Config-file-swap pattern:** `NEXT_CONFIG_FILE` env var is not supported by Next.js — config must be named exactly `next.config.ts`. Gradle `doFirst` copies android config over the original, `doLast` restores it after build. This preserves EccoPath's web dev config untouched.
- **Branch is `master` not `main`:** EccoPath repo uses `master` as its default branch. Submodule tracks `master` (plan said `main` — auto-corrected).
- **APK assets gitignored:** `app/src/main/assets/eccopath/` is build output, regenerated by Gradle. Not committed to the parent repo.
- **force-static on lastfm route:** The CORS proxy API route is server-side only (Vercel). Android WebView has no CORS restrictions so it never calls this route. Marking `dynamic = 'force-static'` unblocks static export without removing the route for Vercel deploys.

### Auto-fixed Issues

**1. [Rule 1 - Bug] EccoPath branch is `master` not `main`**
- **Found during:** Task 1 (submodule add)
- **Issue:** Plan specified `branch = main` but EccoPath repo only has a `master` branch — `git submodule add -b main` fails

**2. [Rule 1 - Bug] `NEXT_CONFIG_FILE` env var not supported by Next.js**
- **Found during:** Task 2 (Gradle task implementation)
- **Issue:** Plan specified `environment("NEXT_CONFIG_FILE", "next.config.android.ts")` but Next.js only reads config files named `next.config.js`, `next.config.mjs`, or `next.config.ts` — the env var is ignored entirely, causing build to use wrong config
- **Fix:** Implemented config-file-swap pattern: `doFirst` copies `next.config.android.ts` to `next.config.ts` (with backup), `doLast` restores the original after build completes
- **Files modified:** `app/build.gradle.kts`
- **Verification:** Ran Next.js build manually with swap in place — produced `out/` directory with static export
- **Committed in:** `9ff34554` (Task 2 commit)

**3. [Rule 1 - Bug] `/api/lastfm` dynamic route blocks `output: export`**
- **Found during:** Task 2 (verifying Next.js static export)
- **Issue:** Next.js static export fails with "export const dynamic = 'force-static'/export const revalidate not configured on route '/api/lastfm' with 'output: export'" — the CORS proxy route is server-rendered and incompatible with static export
- **Fix:** Added `export const dynamic = 'force-static'` to the route handler. This is correct because the route is never called in Android WebView (no CORS restrictions), and on Vercel the route continues to function normally as a server function
- **Files modified:** `eccopath/app/api/lastfm/route.ts`
- **Verification:** `next build` with Android config succeeds, produces `out/index.html`
- **Committed in:** submodule commit `a977157`
