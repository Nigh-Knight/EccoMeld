## Color

All colors via `MaterialTheme.colorScheme.*` — do not hardcode hex values. The theme is dynamic (Material You wallpaper colors on Android 12+, materialKolor seed on older). Default seed: `Color(0xFFED5564)` (rose-red).

| Role | M3 Token | Usage |
|------|----------|-------|
| Dominant (60%) | `colorScheme.background` | Screen background |
| Secondary (30%) | `colorScheme.surface` / `colorScheme.surfaceVariant` | Text field fill, progress bar track background |
| Accent (10%) | `colorScheme.primary` | "Find Bridge" button background (enabled state), progress bar fill, focus ring on active text field |
| Ghost text | `colorScheme.onSurface` at alpha 0.38f | Autocomplete ghost suffix rendered at 38% opacity (Material disabled content alpha) |
| Disabled | `colorScheme.onSurface` at alpha 0.38f | "Find Bridge" button when `isRunning = true`, text fields when bridge is running |
| Destructive | `colorScheme.error` | Inline error message text and any error icon |

Accent reserved for: "Find Bridge" button (enabled state fill), `LinearProgressIndicator` bar fill, focused `OutlinedTextField` border/indicator. Nowhere else in this phase.

Source: Existing `BridgeScreen.kt` uses `MaterialTheme.colorScheme.error` for error state — extended consistently.

## Interaction Contract

### Ghost Text Autocomplete

**Trigger:** User types in either "From" or "To" field. After 300ms debounce with no further keystrokes, call `LastFM.artist.search()` with `limit=1`.

**Ghost rendering:** Use `BasicTextField` with a `decorationBox` or a `Box` overlay approach:
- User's typed text: rendered normally at `colorScheme.onSurface`
- Ghost suffix (completion beyond typed text): rendered at `colorScheme.onSurface` alpha 0.38f, appended inline directly after the cursor position
- Ghost is only shown if the top suggestion starts with the user's typed text (case-insensitive prefix match)

**Confirmation:** Soft keyboard IME action `ImeAction.Done` or a "Tab to confirm" visual hint label. On confirm, the full suggested artist name fills the field and ghost clears. The label below the active field reads "Tab to confirm" (11sp, `labelSmall`, `colorScheme.primary` at 0.6f alpha) when ghost is visible.

**No suggestion:** Ghost clears silently. No error shown for empty autocomplete results.

**Escape / field clear:** Tapping the clear icon resets the field value and ghost.

### "Find Bridge" Button State Machine

| State | Visual | Behavior |
|-------|--------|----------|
| Both fields empty | Disabled — `colorScheme.onSurface` 38% alpha fill | Non-tappable |
| One field filled | Disabled | Non-tappable |
| Both fields filled | Enabled — `colorScheme.primary` fill | Tappable, triggers `BridgeViewModel.startBridge()` |
| `isRunning = true` | Disabled — `colorScheme.onSurface` 38% alpha fill + `CircularProgressIndicator` inside button | Non-tappable, second tap impossible |

Source: CONTEXT.md D-09 — button disabled while `isRunning = true`.

### Progress Display

Shown when `BridgeUiState` is `Searching`. Layout:
1. `LinearProgressIndicator` (Material 3, full width) — determinate when `foundHops > 0` (progress = `foundHops / totalHops.toFloat()`), indeterminate when `foundHops == 0` (analyzing phase)
2. Progress message text (`bodyLarge`) below the bar: sourced from `BridgeProgressInfo.message` (e.g., "Searching from Radiohead…", "Building bridge path…")
3. Hop count text (`bodySmall`, `colorScheme.onSurface` 60% alpha) below the message: "Found {foundHops} of {totalHops} hops" — only shown when `totalHops > 0`

Source: CONTEXT.md D-06, D-07. `BridgeUiState.Searching(foundHops, totalHops)` already carries these fields.

### Error Display

Shown when `BridgeUiState` is `Error`. Layout:
- Inline in the main content area — no dialog, no snackbar
- Error icon (`Icons.Outlined.ErrorOutline`, 20dp, `colorScheme.error`)
- Error headline text (`bodyMedium`, `colorScheme.error`): see Copywriting section
- Suggestion text (`bodyMedium`, `colorScheme.onSurface` 60% alpha): "Try artists from different genres"
- Input fields remain visible and editable above the error — user can immediately retype

Source: CONTEXT.md D-08, D-10.

### Layout Structure

```
Screen (fillMaxSize, background = colorScheme.background)
  Column (verticalArrangement = Arrangement.Top, padding = LocalPlayerAwareWindowInsets)
    Spacer (height = 48dp)
    // Input section
    Row (horizontalArrangement = Arrangement.spacedBy(8dp), padding horizontal 16dp)
      ArtistSearchField("From", weight = 1f)
      ArtistSearchField("To", weight = 1f)
    Spacer (height = 8dp)
    FindBridgeButton (padding horizontal 16dp, fillMaxWidth)
    Spacer (height = 16dp)
    // State-driven section
    when (uiState) {
      Idle -> IdleHintText (centered)
      Searching -> ProgressSection (padding horizontal 16dp)
      PathFound -> PathFoundPlaceholder (Phase 6 fills this in)
      PlaylistReady -> PlaylistReadyPlaceholder (Phase 5 fills this in)
      Error -> ErrorSection (padding horizontal 16dp)
    }
```

Side-by-side "From" / "To" with `weight(1f)` each inside a `Row` with `Arrangement.spacedBy(8dp)` and 16dp horizontal screen padding. Handles narrow screens gracefully — each field gets exactly half the available width minus 4dp gap.

Source: CONTEXT.md D-03, D-04. EccoPath `SeedSearch.tsx` ghost text pattern adapted to Compose.

## Accessibility Contract

- Both text fields must have `contentDescription` matching their label ("From artist search field", "To artist search field")
- Ghost text overlay must be `aria`-equivalent `Modifier.semantics { invisibleToUser() }` — ghost is purely visual decoration, not read by TalkBack
- "Find Bridge" button disabled state must use `enabled = false` (not alpha alone) so TalkBack announces it as "dimmed" or "unavailable"
- Progress bar: `LinearProgressIndicator` with `Modifier.semantics { progressBarRangeInfo(...) }` for screen reader announcements
- Error section: wrap in `Modifier.semantics { liveRegion = LiveRegionMode.Polite }` so TalkBack announces the error when it appears without user focus
