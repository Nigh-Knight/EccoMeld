## Color

All colors via `MaterialTheme.colorScheme.*` — do not hardcode hex values. Dynamic Material You theming applies. Default seed: `Color(0xFFED5564)` (rose-red).

| Role | M3 Token | Usage |
|------|----------|-------|
| Dominant (60%) | `colorScheme.background` | Screen background |
| Secondary (30%) | `colorScheme.surface` / `colorScheme.surfaceVariant` | Chip container background (unselected), FAB container background |
| Accent (10%) | `colorScheme.primary` | FAB icon tint, "NEW" badge background, chip selected state border |
| Muted accent | `colorScheme.secondary` | "known" badge background |
| On-accent | `colorScheme.onPrimary` | Text on "NEW" badge, FAB icon |
| On-muted | `colorScheme.onSecondary` | Text on "known" badge |
| Disabled | `colorScheme.onSurface` at alpha 0.38f | Chip text when seed row is loading |
| Destructive | `colorScheme.error` | (Inherited from Phase 4 — error states only) |

Accent reserved for: FAB icon tint, "NEW" badge background fill, chip selected-state border highlight. Nowhere else in this phase.

Badge color rationale (Claude's discretion, per CONTEXT.md):
- "NEW" badge uses `colorScheme.primary` fill + `colorScheme.onPrimary` text — high contrast, signals discovery.
- "known" badge uses `colorScheme.secondary` fill + `colorScheme.onSecondary` text — lower visual weight, signals familiarity without competing with "NEW".

Source: Extends Phase 4 color contract. Badge design chosen by Claude per CONTEXT.md D-11.

## Interaction Contract

### Seed Suggestion Chips Row

**Placement:** Directly below the "From" / "To" input row and above the "Find Bridge" button. Appears only when at least one artist is available from either Spotify liked artists or YT Music library.

**Layout:**
```
// Seed suggestions row (visible only when suggestions.isNotEmpty())
LazyRow(
    contentPadding = PaddingValues(horizontal = 16dp),
    horizontalArrangement = Arrangement.spacedBy(8dp)
) {
    items(suggestions, key = { it.name }) { artist ->
        SuggestionChip(
            label = { Text(artist.name, style = MaterialTheme.typography.labelLarge) },
            onClick = { fillEmptyOrFocusedInput(artist.name) }
        )
    }
}
```

**Fill behavior (D-01):** Tapping a chip fills whichever of "From" / "To" is currently empty or focused:
1. If "From" is empty — fill "From".
2. If "From" is filled and "To" is empty — fill "To".
3. If both are filled and "From" is focused — overwrite "From".
4. If both are filled and "To" is focused — overwrite "To".
5. If both are filled and neither is focused — fill "From" (fallback).

**Loading state:** While seed data is loading, show 3 placeholder chips (shimmer animation using `compose-shimmer`, consistent with existing shimmer usage in the app). Placeholder chip width: 80dp each.

**Empty state:** Row is hidden (`isVisible = false` via `AnimatedVisibility`) when `suggestions.isEmpty()` after loading completes. No empty state text shown — the section simply disappears (D-12).

**Deduplication (D-04):** Deduplication is ViewModel responsibility. UI renders whatever list `BridgeViewModel.seedSuggestions` emits. No UI-layer dedup logic.

**Cap:** Show a maximum of 20 chips. If the combined artist count exceeds 20, prefer artists appearing in both sources first (already deduplicated), then Spotify liked artists, then YT Music library artists by recency. Cap enforced in ViewModel, not in UI.

**Loading trigger:** Load eagerly when the Bridge tab becomes visible — `LaunchedEffect(Unit)` in `BridgeScreen` calling `viewModel.loadSeedSuggestions()`.

### Random Bridge FAB

**Placement:** Bottom-end corner of the Bridge screen (`Scaffold` `floatingActionButton` slot). Always visible regardless of Spotify connection state (D-05).

**Component:** `FloatingActionButton` (standard size, 56dp).

**Icon:** `Icons.Outlined.Shuffle` — communicates randomness and discovery without requiring bespoke iconography.

**Label:** No extended FAB label. Icon only. Content description: `"Random Bridge"`.

**Color:** FAB uses `FloatingActionButtonDefaults.containerColor` (which resolves to `colorScheme.primaryContainer`) with icon tint `colorScheme.onPrimaryContainer`. This keeps the FAB visually prominent without hardcoding the accent.

**Tap behavior (D-08):**
1. ViewModel fetches Last.fm tags for a sample of library artists (background, cached).
2. Selects two genre-opposite artists via Tag Jaccard distance.
3. Fills "From" and "To" inputs.
4. Immediately calls `BridgeViewModel.startBridge()`.
5. FAB shows `CircularProgressIndicator` (16dp, `colorScheme.onPrimaryContainer`) inside the FAB during selection — no label change, spinner replaces icon.

**Insufficient artists toast (D-06):** If fewer than 2 artists are available from all sources combined, tap shows a `Toast` with text "Add some artists to your library first" (string resource `bridge_random_no_artists`). FAB does not enter loading state in this case.

**Disabled-while-running:** FAB is non-interactive (`enabled = false`) while `isRunning = true` to prevent concurrent bridge starts. Alpha does not change — use `enabled = false` so TalkBack announces state correctly.

### Known/NEW Badges

**Placement:** On each bridge artist node in the Phase 6 linear path view (bottom sheet or card row). Rendered as a small pill badge within the artist node composable.

**Dimensions:** 16dp height, horizontal padding 8dp each side, corner radius 8dp (fully rounded pill). No icon — text only.

**"NEW" badge:**
- Background: `colorScheme.primary` at alpha 1.0f
- Text: `colorScheme.onPrimary`, `labelSmall` (11sp, Medium 500)
- Text copy: "NEW"
- Shown when: artist name is not found in `ArtistEntity` Room table AND not in Spotify liked artists (D-10)

**"known" badge:**
- Background: `colorScheme.secondary` at alpha 0.7f
- Text: `colorScheme.onSecondary`, `labelSmall` (11sp, Medium 500)
- Text copy: "known"
- Shown when: artist name found in `ArtistEntity` Room table OR in Spotify liked artists (D-10)

**No badge:** If badge resolution has not completed yet (still loading), no badge placeholder is shown — node renders without a badge until data arrives. Avoids layout shift.

**Badge resolution:** Resolved in ViewModel, not in UI. `BridgeViewModel` emits a `Map<String, ArtistFamiliarity>` (where `ArtistFamiliarity` is `NEW` or `KNOWN`) alongside the path result. UI reads this map by artist name.

### Layout Structure (BridgeScreen additions)

**Primary focal point:** Find Bridge button (inherited from Phase 4). **Secondary anchor:** Random Bridge FAB (bottom-end corner, persistent).

The Phase 4 layout structure is extended as follows:

```
Screen (fillMaxSize, background = colorScheme.background)
  Scaffold(
    floatingActionButton = { RandomBridgeFab(...) }
  ) { paddingValues ->
    Column(verticalArrangement = Arrangement.Top, padding = LocalPlayerAwareWindowInsets + paddingValues)
      Spacer(height = 48dp)
      // Input section (Phase 4 — unchanged)
      Row(horizontalArrangement = Arrangement.spacedBy(8dp), padding horizontal 16dp)
        ArtistSearchField("From", weight = 1f)
        ArtistSearchField("To", weight = 1f)
      Spacer(height = 8dp)
      // Seed suggestions row (NEW in Phase 7)
      AnimatedVisibility(visible = seedSuggestions.isNotEmpty() || isLoadingSeeds)
        LazyRow(contentPadding = PaddingValues(horizontal = 16dp), spacing = 8dp)
          [SuggestionChip items or shimmer placeholders]
      Spacer(height = 8dp)
      FindBridgeButton(padding horizontal 16dp, fillMaxWidth)  // Phase 4 — unchanged
      Spacer(height = 16dp)
      // State-driven section (Phase 4 — unchanged structure, Phase 6 fills PathFound)
      when (uiState) {
        Idle -> IdleHintText(centered)
        Searching -> ProgressSection(padding horizontal 16dp)
        PathFound -> LinearPathView(nodes with known/NEW badges)  // Phase 6+7
        PlaylistReady -> LinearPathView(nodes with known/NEW badges, playback highlight)
        Error -> ErrorSection(padding horizontal 16dp)
      }
  }
```

Source: CONTEXT.md D-01, D-05, D-08, D-09. Extends Phase 4 UI-SPEC layout.

- Badge copy is intentionally lowercase "known" and uppercase "NEW" — asymmetry signals that "NEW" is the notable discovery state, "known" is the neutral baseline.

## Accessibility Contract

- Seed chips: each chip `contentDescription` = artist name (already provided by chip label, no override needed)
- Shimmer placeholder chips: `Modifier.semantics { contentDescription = stringResource(R.string.bridge_seeds_loading_description) }` on the `LazyRow` container, individual shimmer items `invisibleToUser()`
- FAB: `contentDescription = stringResource(R.string.bridge_random_fab_description)` — always set even when showing spinner (description does not change during loading)
- FAB disabled state during bridge run: `enabled = false` so TalkBack announces "unavailable"
- "NEW" badge: `contentDescription = "New artist"` (expanded form, not abbreviated)
- "known" badge: `contentDescription = "Familiar artist"`
- Badges are supplementary — do not use `liveRegion`; they appear alongside artist names the user is already reading
